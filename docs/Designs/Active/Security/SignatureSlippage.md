# Signature slippage: the small-order Ed25519 acceptance

Campaign opened 2026-10-07 by Damian: "fix the defect, let all lanes come to a
halt after their current unit, and put 100% effort on the fix, verification,
analysis of the slippage shape, examination of blast radius that slippage shape
could impact, and audit and fix all that. then we release." And: "this code has
been built and audited numerous times by all frontier agents for the last 6

after-action report. Like the o-ring nasa disaster."

Every lane works only this campaign until root closes it. The release follows
the close; red runs it.

## The defect (red, 2026-10-07)

`ed25519-verify` (`codex/foreword/core/Ed25519.codex`) accepts a small-order
public key A and a small-order R. An unsigned CDX (zero key, zero signature)
passes the signature check whenever the challenge hash h satisfies
h mod 4 = 3, about 1 in 4 hashes. Found because a COMPILER-127 candidate landed
in that class and `cdx-chain` went red, predicted and then confirmed.

## The slippage shape (working statement, the report refines it)

A verifier checked its equation and never checked that its inputs lie in the
domain the equation is sound over. Every test fed it well-formed inputs, so
every test agreed (L-ORACLE: a harness validates only the half it points at).
The shape to hunt anywhere: a check that ANSWERS on a degenerate input (zero,
identity, small-order point, out-of-range scalar, empty or short tag, failed
entropy read) instead of refusing (L-BAILVALUE).

## Part B: the callers of `ed25519-verify` (blu)

Confirmed independently on seed 442CAED8 (pre-fix), h computed outside Codex
(.NET SHA-512 over R, A, M, reduced mod L): A = 32 zero bytes and a 64-byte
zero signature verify M = [10] + 31 zeros and [11] + 31 zeros (h mod 4 = 3) and
are refused for [2], [6], [12] (classes 0, 1, 2). Real compiler output, unsigned
(key and signature zero) with its content hash recomputed in .NET: the labor,
farmer and fighter proof CDXs (class 3; labor's hash `e977d3b1...a78ed8e`) pass
`cdx-verify-signature`, three in classes 0 to 2 are refused. Seed 279DF926
(part A) refuses all eleven.

The defect passes a forgery only under a key the forger chooses; against a
prime-order key it gives nothing. A caller is exposed exactly where it verifies
under a key the signed object itself supplies, and there a forgery buys what a
freshly generated honest key buys, unless the caller then trusts that key.
Census over `codex/`, `apps/`, `tools/`, `build/` by the name and by the one
wrapper, `cdx-verify-signature` (`os/verify/CdxBinary.codex:160`), tests
excluded (2026-10-07): 18 direct call sites and 3 chapters through the wrapper.
`codex/test/apps/ed25519-callers-small-order` drives the two callers whose
message is their input verbatim (a CDX header's stored hash, a handshake nonce)
with red's four vectors: class 3 accepted on 442CAED8, all four refused on
279DF926. Every other caller hands the key and message straight to the
primitive, so part A's `ed25519-small-order` is its arm.
