| WORKS-25 | **A second xHCI bring-up destroys the keyboard and mouse the first one bound** | `GopUsbMsc` calls `xhci-connect` (line 177), which re-scans PCI and brings the controller up from scratch -- halt then HCRST -- with no regard for one already running. On the desk that fires from `desk-font`: mount the ESP, find no IDE or AHCI medium, try the USB one, and the controller `usb-attach` had already bound the keyboard and mouse to is reset underneath them. **Measured on codex-vm 2026-08-13 (val):** with no disk the guest resets the SAME controller twice (identical host pointer) and then rings NO endpoint for the rest of the session; with a disk attached it resets once, rings slot 5 ep 3 and slot 2 ep 5, and the pointer moves -- 245 cursor pixels where the timeline put it. **The keyboard hides it:** codex-vm keeps feeding the legacy PS/2 mailbox that `gk-take` reads, so keys keep working while USB is dead, and the Monitor pane still reads "keyboard USB HID   mouse yes" because `uk-ok`/`um-ok` record that ENUMERATION succeeded, which is a different claim from the transport being live. The mouse has no mailbox fallback, so it simply stops. **The fix is to make `xhci-connect` reuse a controller that is already up** rather than reset it; its three callers (`GopUsbMsc`, `GopUsbKbd`, `CamCapture`) all want an existing host, not a fresh one. `XhciHost` carries eight allocated addresses, so caching it needs diag cells chosen against the band map in `GopXhci` -- read the "SNAPSHOT OWNS EIGHT CELLS" note there first. `build/desk.ps1` attaches a disk by default (main 14908) so the dev box does not walk into this, which is a bed change and NOT the fix. |

| WORKS-14 | **The editor has no keystroke undo, and cannot create a file** | Editing and save landed 2026-08-11: type, Enter to split, Backspace and Delete, F2 to save, and every save keeps ONE generation as `NAME.BAK` (Damian's rule: a hot backup so a save can be undone, and two saves back is asking too much).
