# Sheets -- open capabilities

App-domain backlog. The shape and priority order for the platform live in
`docs/PM/CurrentPlan.md`; the platform-wide register was deleted 2026-07-23
and is not coming back. Anything that is this application's own behaviour
lives here.

The rules are the same ones: an entry says what is still missing and
nothing else, a closed entry is DELETED rather than annotated, and a
gap that is still real is never quietly dropped.

The design is `docs/Designs/Active/Apps/Sheets.md`. Built as of 2026-09-08:
the cell store (`apps/sheets/CellStore.codex`), csv in and out
(`apps/sheets/CellCsv.codex`), the formula parser
(`apps/sheets/CellFormula.codex`), the dependency graph
(`apps/sheets/CellGraph.codex`), the evaluator with its function set
(`apps/sheets/CellEval.codex`) and the desk pane
(`apps/works/GopSheet.codex`), with arms `codex/test/apps/sheet-cell-store`,
`codex/test/apps/sheet-csv`, `codex/test/apps/sheet-formula`,
`codex/test/apps/sheet-graph`, `codex/test/apps/sheet-eval`,
`codex/test/apps/sheet-chain` and the sheet itself
(`apps/sheets/CellView.codex`, arm `codex/test/apps/sheet-view`).

**The parser's contract, because SHEET-3 is its consumer.**
`formula-parse` takes the whole formula text including the leading `=` and
answers a `FxParse` whose `px-ok` is the discriminator; a refusal carries a
message and the byte offset it stopped at, and its `px-expr` means nothing.
`formula-refs` walks a parsed `Expr` and answers the edge set as a
`List CellRef`, each carrying its row, its column and the spelling the person
wrote. A range contributes its two CORNERS, not the cells between them:
enumerating those needs the sheet's bounds, which the parser does not have.
Comparison is non-associative, and a formula must be consumed whole.

The rows below are what is left. The app is
listed on the landing page as of 2026-08-26 under that section's "partially
built" wording.

| SHEET-3 | **The dependency graph, built. Its contract, because SHEET-4 and SHEET-7 are the consumers** | `apps/sheets/CellGraph.codex`, arm `codex/test/apps/sheet-graph`. A `Program` holds a sheet block plus a formula table keyed by cell; `graph-put` parses and REPLACES any formula already at that cell. `graph-plan` answers a `Plan` whose `pl-ok` is the discriminator: an order of formula-entry indices, or a refusal naming the cells. A parse failure is reported BEFORE the sort. A cycle leaves exactly its members unemitted by Kahn's algorithm, and `pl-stuck` plus `pl-msg` name them. `graph-dependents` answers the transitive dependents of an edited cell as a SUBSEQUENCE of the derived order; the edited cell is included, and a cell holding no formula (the common edit) takes as roots the formulas naming it directly. A range is expanded HERE and not by the parser, because the bounds live here. Adjacency is CSR over dense blocks, so the sort is one pass over vertices plus one over edges. What is NOT here is evaluation: nothing computes a cell's value yet, and that is SHEET-4. |
| SHEET-4 | **The evaluator and the function set, built. The rulings a reader needs** | `apps/sheets/CellEval.codex`, arm `codex/test/apps/sheet-eval`. All four stages: arithmetic and comparison, `SUM`/`COUNT`/`MIN`/`MAX`/`AVERAGE`, `IF`/`SUMIF`/`COUNTIF`, `CONCAT`/`LEN`/`UPPER`/`LOWER`/`TRIM`. **A formula is TYPED: `=A1+B1` with text in `B1` refuses NAMING `B1`.** A text value carries its origin cell, because an operator sees values rather than expressions and a refusal that could not name the cell would be useless. An error propagates unchanged, so the message reaching the top names the cause. An EMPTY cell is a distinct value: zero in arithmetic, skipped by ranges and `COUNT`, and never equal to the number 0 in `COUNTIF`. A range skips text and empty rather than refusing, because a label above a column is the normal shape of a sheet. `MIN`, `MAX` and `AVERAGE` over no numbers REFUSE. `AVERAGE` truncates, because a cell holds a 32-bit integer. Text compares for equality only: an ordering on text is a collation decision and a byte order is not one. `SUMIF`/`COUNTIF` take a VALUE to match exactly, never a criterion string like `">5"`, which would be a second expression language reachable only at runtime. `LEN` counts code points; `UPPER`/`LOWER` fold ASCII only and pass multi-byte sequences through; `TRIM` strips the ends and does not collapse runs inside. |
| SHEET-6 | **Lookup, built to the ruling. Its contract** | `LOOKUP(range, key, header)` in `apps/sheets/CellEval.codex`, arm `codex/test/apps/sheet-lookup`. The range's FIRST ROW is the header row and its FIRST COLUMN is the key column; the key matches EXACTLY, and the answer comes from the column whose header equals `header`. Positional `VLOOKUP` does not ship: a lookup keyed on column POSITION is wrong the first time somebody inserts a column, and nothing in the sheet says so. Three refusals, each naming what a person can act on: no column carries that header, no row carries that key, or MORE THAN ONE row does. The last is the one other spreadsheets answer instead of refusing, and taking the first row is a near match wearing an exact match's clothes. Compatibility for a sheet arriving from elsewhere is an import concern, registered here only if it ever bites. |

| SHEET-8 | **No quadratic line in Sheets. Measured at two sizes** | Closed. Every accumulator in `CellGraph` and `CellEval` is built with `list-push`, which extends in place, rather than `acc & [x]`, which allocates a fresh list of length 1, 2, 3 and so on. **A `Program` is a WORKBOOK, not a value: `graph-put` extends it in place and answers the same workbook, and an earlier binding names the same workbook.** That contract is stated in the chapter rather than avoided, because avoiding it was the quadratic; `pg-slot` was already a shared block, so a `Program` was never a value a caller could hold two versions of, and the cell list was the half pretending otherwise. Measured 2026-09-08 on seed F6A07B16 by `codex/test/apps/sheet-chain` at 1,000 and 4,000 cells: build 12,956 and 14,999 bytes a cell (the rise is the formula text getting longer, `=A3999+1` against `=A9+1`), recalculation 1,340,368 and 5,363,280 bytes, which is 4.00x for four times the cells. Recalculation at 1,000 cells fell from 17,467,024 bytes to 1,340,368 over the two passes, 13x. Two sizes, because one number cannot say whether a cost is linear. |
