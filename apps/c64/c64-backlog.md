# C64 -- open capabilities

App-domain backlog. There is no platform-wide register any more:
`docs/PM/BACKLOG.md` was deleted 2026-07-23 and must not be recreated.
`docs/PM/CurrentPlan.md` carries the shape and the priority order for
the platform. Anything that is this application's own behaviour lives
here.

The rules are the same ones: an entry says what is still missing and
nothing else, a closed entry is DELETED rather than annotated, and a
gap that is still real is never quietly dropped.

| # | Capability | State of the gap |
|---|---|---|
| C64-2 | **The browser module builds** | `C64Wasm.codex`, `build-wasm.ps1`, the page at `apps/landing/web/c64/`, the grader `c64-verify.mjs` and the landing card are all written and land together; the MODULE does not build, and the cause is not in this app. The wasm plug splices a literal pattern's SPELLING into `(i64.const ...)` (`codex/plugs/wasm/WasmEmitter.codex:1245`, `wat-lit-pat-const`), so a `when` arm written `is #A9 ->` reaches `wat2wasm` as `(i64.const #A9)` and it refuses. `Cpu6502.codex` dispatches ~150 opcodes exactly that way, so no module assembles at all. Measured 2026-09-02 with a four-arm repro: a hex pattern fails, a DECIMAL pattern in the same `when` and the SAME hex literal in an expression and in an `if` all emit clean decimal. The emitter's own prose at `:1251` records this class for Text literals ("the one literal whose SPELLING is not its value") and the hex case is the same bug unfixed. Routed to reek 2026-09-02, who owns the file and accepted it. **Do not work around it by respelling the opcode table in decimal**: that is app source bending around a plug gap, and it would destroy the one table where hex is the only readable notation. |
| C64-3 | **The SID and the CIAs stop sharing an address** | `Memory.codex` sets `sid-state : Integer = #A16000` and `Cia.codex` sets `cia-state : Integer = #A16000`. They are different names in different chapters, so nothing warns. SID occupies offsets 0-31 (`c64-read-io-reg` masks `bit-and (addr - #D400) 31`); CIA1 occupies 16-31 (`cia1-read`/`cia1-write` index `16 + reg`) and CIA2 32-47. So SID registers 16-31 ARE CIA1's registers 0-15. Concretely: SID 17 is voice 3's frequency high byte and CIA1 1 is the keyboard column read, so a program making sound on voice 3 writes the keyboard matrix, and `OdeToJoy.codex` in this app is such a program. `vic-state` is at #A17000, so there is a clear 4 KB between them and the fix is to give the CIAs their own base. Found 2026-09-02 by an address census while porting to wasm; NOT fixed there, because the port ships the bare-metal behaviour rather than changing it. |
| C64-4 | **The browser and bare-metal machines stop being two copies** | `C64Wasm.codex` carries its own `c64w-run-cycles`, `c64w-run-raster`, `c64w-init-ram`, `c64w-init-vic` and the whole glyph renderer, each a retargeted copy of the same function in `opening.codex`. The renderer genuinely differs (a low framebuffer, and the palette pre-swapped to the byte order a canvas wants), but the raster loop, the cycle loop and the two init functions differ in nothing but their names. They were copied rather than shared because `opening.codex` is the bare-metal ENTRY: it holds `gop-fb : Integer = #BF000000` and an effectful `opening`, so citing it drags both into a browser module. The fix is a chapter holding the machine, cited by both entries, with the framebuffer base passed in rather than baked. Deliberately not done inside the port (R-ONE): it changes the bare-metal app to serve the browser one. |
| C64-1 | **Chapters in this app stop sharing definition names** | Measured 2026-07-21 by `build/sweep-app-classes.ps1 -Jobs 6` (2.6 min, 266 entry units; parse `test-output/clssweep/*.log` for `warning CDX3006`). **Duplicated between this app's own chapters** (prefix one, or extract a shared chapter): `c64-ram` (Cpu6502 vs C64--Memory, 1u); `c64-ram` (Memory vs C64--Cpu6502, 1u); `char-rom` (Memory vs C64, 1u); `color-ram-base` (Memory vs C64, 1u); `gop-fb` (VicII vs C64, 1u); `gop-height` (VicII vs C64, 1u); `gop-width` (VicII vs C64, 1u). CDX3006 is a warning, not an error: each chapter sees its own definition, so this compiles and runs. What it costs is that a mention in a chapter defining NEITHER resolves by the order the build globs files, and moving a body between chapters silently changes what it means. **Compare the bodies before merging a pair -- same name does not mean same function**, and a pair whose arities differ cannot be merged at all.  |
