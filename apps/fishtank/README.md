# Codex FishTank

A WebGPU aquarium simulation with boids-based fish AI, procedural 3D mesh generation, volumetric god rays, particle systems (bubbles, food, ambient specks), and a day/night cycle. Two renderer generations: v1 (full 3D procedural meshes for fish and 50+ decorations) and v2 (photorealistic reef with billboarded sprites and parallax foreground layers).

## Modules

### Types and Scene Data
- **FishTankTypes** -- Domain record types: FishSpecies, BodyStation, FinDef, TailDef, FishBody, FishProfile, DecorSprite, TankBounds, SpawnOrder, AquariumScene
- **FishTankScene** -- Scene instantiation: 8 fish species with boid parameters, 8 body profiles with cross-section stations, 11 decoration sprites, 8 spawn orders, tank bounds

### Shaders and CSS
- **FishTankShaders** -- WGSL shader source as Codex Text constants: background (scrolling reef, god rays, day/night), sprite (billboarded fish with tail-wiggle vertex animation, depth fog), particle (bubbles, food flakes, ambient specks), ABZU-style 4-layer 3D fish mesh shader
- **FishTankCss** -- Full page CSS: viewport canvas, frosted-glass HUD bar, controls bar, species labels, Add Fish dropdown

### Renderers (JS stored as Codex text constants)
- **FishTankBridge** -- v2 photorealistic reef renderer (22 text segments): SoA fish state, WGSL shaders, procedural 3D fish mesh generator, GLB loader, perspective/lookAt math, texture atlas packing, boids AI, particle system, WebGPU init/render loop, HUD/controls
- **FishTankV1Bridge** -- v1 3D procedural renderer (10 text segments): 6 mesh generators (sphere, cylinder, dome, flat disc, rock, sea fan), per-species fish body profiles, 50+ decoration items, sand floor with caustics, full boids AI

### Emitters
- **FishTankEmit** -- v1 emitter: walks AquariumScene record tree, serializes to JS constants, assembles complete HTML page to stdout
- **FishTankPage** -- v2 page assembler: streams FishTankBridge text segments with CSS into a complete HTML page

### WASM
- **FishTankWasm** -- Species data and tank bounds as flat integer lookup functions for WASM export (currently stubbed opening)

### Asset Pipeline (PowerShell)
- **generate-assets.ps1** -- Generates fish/coral/environment textures via Stable Diffusion API
- **generate-creatures.ps1** -- Generates extended creature and decoration textures

## Completeness

70% -- Three pages. v1 (3D meshes) and v2 (photorealistic reef) run the simulation in JS held as Codex text constants. The WASM page (`fishtank-wasm.html`) runs it in Codex compiled through the WASM plug: it calls `init_aquarium` once and `tick` per frame, and reads fish and particle state straight out of WASM linear memory at the addresses `FishTankWasm.codex` writes. Boids AI, particle systems, day/night cycle, and HUD all work. Gaps: the v2 renderer has GLB loading code present but disabled (`use3DMeshes = false`); no bare-metal entry point (browser-only app).

## Codex Conformance

Partial -- All source lives in .codex files. The emitters generate HTML pages from Codex data, which is the correct plug pattern. However, the renderer runtime (boids AI, mesh generation, WebGPU init) is stored as JS text constants in FishTankBridge/FishTankV1Bridge rather than being compiled from Codex logic through the WASM plug. FishTankWasm is that approach and `fishtank-wasm.html` is wired to it; the v1 and v2 pages are not. The end goal is: fish logic in Codex compiled to WASM, shaders in FishTankShaders, thin JS bridge generated by the HTML plug.
